\subsection{กระบวนการวิทยาการข้อมูลและการจัดทำท่อส่งข้อมูล (Data Science \& Pipeline Process)}

กระบวนการวิทยาการข้อมูลเป็นกรอบการทำงานเชิงระบบที่นำข้อมูลขนาดใหญ่มาประมวลผลและวิเคราะห์ เพื่อค้นหารูปแบบหรือสร้างคุณประโยชน์ ในโครงงานนี้ได้ประยุกต์ใช้กระบวนการ 5 ขั้นตอน ร่วมกับการออกแบบท่อส่งข้อมูลแบบโมดูลาร์ (Modular Data Pipeline) ได้แก่

\begin{enumerate}[label=\arabic*)]
    \item \textbf{การกำหนดวัตถุประสงค์และคำถามวิจัย (Question Refinement):} กำหนดโจทย์ในการทำนายผลการแข่งขันฟุตบอลออกเป็น 3 รูปแบบ ได้แก่ ทีมเจ้าบ้านชนะ (Home Win: H), เสมอ (Draw: D) และทีมเยือนชนะ (Away Win: A)
    \item \textbf{การเก็บรวบรวมข้อมูล (Data Collection):} การสร้างระบบดึงข้อมูลอัตโนมัติ เพื่อรวบรวมตารางการแข่งขัน ผลประตู ค่า xG และสถิติรายบุคคลของผู้เล่นจาก Understat และปฏิทินการแข่งขันทุกรายการของสโมสรจาก Transfermarkt รวมถึงชุดข้อมูลผลการแข่งขันพรีเมียร์ลีกจาก Kaggle \cite{kaggle2024, transfermarkt2024, understat2024}
    \item \textbf{การตรวจสอบ ทำความสะอาด และสร้างตัวแปร (Data Validation \& Feature Engineering):} การตรวจสอบคุณภาพข้อมูลผ่านสัญญาข้อมูล (Data Contracts) การจัดการค่าที่ขาดหาย การจับคู่ชื่อสโมสร (Entity Resolution) และการสร้างตัวแปรก่อนการแข่งขัน เช่น คะแนน Elo, ดัชนีความเหนื่อยล้า, ความหนาแน่นของตารางแข่งขัน และฟอร์มของผู้เล่นตัวจริง
    \item \textbf{การสร้างและประเมินแบบจำลอง (Model Building \& Evaluation):} การพัฒนาแบบจำลองเพื่อทำนายความน่าจะเป็นของผลการแข่งขัน และประเมินประสิทธิภาพด้วยตัวชี้วัด Log Loss, Ranked Probability Score (RPS) และ Accuracy \cite{scikit-learn}
    \item \textbf{การสรุปและวิเคราะห์ผลลัพธ์ (Communication \& Feature Analysis):} การสรุปผลการวิเคราะห์ เปรียบเทียบกับค่าพื้นฐานและงานวิจัยที่ผ่านมา และนำเสนอระดับความสำคัญของตัวแปรทำนาย (Feature Importance)
\end{enumerate}

\subsection{ระบบวัดระดับความแข็งแกร่ง (Elo Rating System)}

ระบบคะแนน Elo เป็นวิธีทางสถิติที่ใช้คำนวณระดับทักษะความแข็งแกร่งของทีมแข่งขัน คะแนนจะถูกปรับเปลี่ยนตามผลการแข่งขันจริงและระดับความแข็งแกร่งของคู่แข่ง โดยทีมที่ชนะทีมที่มีคะแนนสูงกว่าจะได้คะแนนเพิ่มขึ้นมากกว่าการชนะทีมที่อ่อนกว่า \cite{hvattum2010using} สำหรับฟุตบอล การปรับคะแนนสามารถถ่วงน้ำหนักตามผลต่างประตูของการแข่งขันได้ เพื่อให้ชัยชนะที่ขาดลอยส่งผลต่อคะแนนมากกว่าชัยชนะเฉียดฉิว ในโครงงานนี้ได้มีการคำนวณค่า Elo Rating ของแต่ละสโมสรอย่างต่อเนื่องตามลำดับเวลา (Time-series) ดังแสดงในรูปที่ \ref{fig:elo_concept} และนำผลต่างคะแนน Elo (Elo Difference) ระหว่างทีมเจ้าบ้านและทีมเยือน ซึ่งใช้ค่าก่อนเริ่มการแข่งขันเท่านั้น มาใช้เป็นตัวแปรสำคัญในการสะท้อนความได้เปรียบเชิงศักยภาพของทีม

\subsection{ค่าความคาดหวังในการทำประตู (Expected Goals: xG)}

ค่า xG เป็นตัวชี้วัดเชิงสถิติขั้นสูงที่ใช้ประเมินคุณภาพของโอกาสในการยิงประตู โดยคำนวณความน่าจะเป็นที่ลูกยิงแต่ละครั้งจะกลายเป็นประตู (มีค่าระหว่าง 0 ถึง 1) ขึ้นอยู่กับตำแหน่งการยิง มุมในการยิง ประเภทการส่งบอล และบริบทของเกม ดังแสดงตัวอย่างในรูปที่ \ref{fig:xg_concept} ค่า xG ช่วยให้มองเห็นประสิทธิภาพเกมรุกที่แท้จริง ซึ่งสะท้อนฟอร์มการเล่นได้ดีกว่าผลสกอร์แพ้-ชนะแบบดั้งเดิม \cite{understat2024} ในโครงงานนี้ ค่า xG และค่า xA (Expected Assists) รายบุคคลถูกนำมาสรุปเป็นฟอร์มของผู้เล่นตัวจริงแต่ละคน ในรูปอัตราต่อ 90 นาที โดยใช้เฉพาะการแข่งขันก่อนนัดปัจจุบัน

\subsection{ดัชนีความเหนื่อยล้าและความหนาแน่นของตารางแข่ง (Fatigue Metric \& Schedule Congestion)}

ระยะเวลาพักผ่อนระหว่างแมตช์การแข่งขันส่งผลต่อสภาพร่างกายและประสิทธิภาพการเล่นของนักเตะ ในโครงงานนี้จึงสร้างตัวแปรที่เกี่ยวข้องกับภาระการเล่นเป็น 2 ระดับ ดังแสดงตัวอย่างแนวคิดในรูปที่ \ref{fig:fatigue_concept}

\begin{enumerate}[label=\arabic*)]
    \item \textbf{ระดับผู้เล่น:} คำนวณคะแนนความเหนื่อยล้า (Fatigue Score) ช่วง 0--100 จากนาทีที่ลงเล่นใน 7 วันก่อนหน้า ความสั้นของระยะพัก จำนวนนัดที่ลงเล่นติดต่อกัน และอัตราส่วนภาระงานระยะสั้นต่อระยะยาว (Acute-to-Chronic Workload Ratio) แล้วสรุปเป็นค่าเฉลี่ยของผู้เล่นตัวจริงแต่ละฝั่ง
    \item \textbf{ระดับทีม:} คำนวณจากปฏิทินการแข่งขันทุกรายการ ได้แก่ จำนวนวันพักนับจากนัดก่อนหน้า จำนวนนัดใน 7 และ 14 วันที่ผ่านมา จำนวนนัดที่ไม่ใช่ลีกใน 14 วัน และการเดินทางไปเยือนในศึกยุโรปในนัดก่อนหน้า
\end{enumerate}

\subsection{อัตราต่อรองของเจ้ามือรับพนัน (Betting Market Odds) ในฐานะเกณฑ์อ้างอิงของงานวิจัย}

อัตราต่อรองในตลาดเดิมพันสามารถแปลงเป็นค่าความน่าจะเป็นโดยนัย (Implied Probability) ซึ่งงานวิจัยหลายฉบับใช้เป็นเกณฑ์อ้างอิงมาตรฐาน (Benchmark) ในการวัดประสิทธิภาพของแบบจำลองทำนายผลฟุตบอล เนื่องจากสะท้อนข้อมูลและสภาพตลาดจริง \cite{hubacek2021forty} อย่างไรก็ตาม โครงงานนี้\textbf{ไม่ได้ใช้อัตราต่อรองเป็นตัวแปรนำเข้าหรือเป็นเกณฑ์เปรียบเทียบ} แต่นำมากล่าวถึงเพื่อเป็นบริบทในการอ่านผลการศึกษาของงานวิจัยที่ผ่านมา

\subsection{การจับคู่และแปลงชื่อเอนทิตีให้เป็นมาตรฐาน (Entity Resolution)}

เนื่องจากข้อมูลถูกรวบรวมมาจากหลายแหล่งข้อมูลภายนอก ทำให้ชื่อสโมสรฟุตบอลเดียวกันอาจถูกบันทึกด้วยข้อความที่แตกต่างกัน (เช่น \texttt{"Man Utd"}, \texttt{"Manchester Utd"} และ \texttt{"Manchester United"}) กระบวนการ Entity Resolution จึงถูกนำมาใช้เพื่อปรับแปลงชื่อทีมจากทุกแหล่งข้อมูลให้อยู่ในรูปแบบมาตรฐาน (Canonical Team Names) ผ่านพจนานุกรมเทียบเคียงชื่อ (Alias Mapping) เพื่อให้สามารถเชื่อมโยงข้อมูล (Data Joining) จากต่างแหล่งได้ ทั้งนี้ สโมสรที่ไม่สามารถจับคู่ได้จะมีตัวแปรที่ต้องอาศัยแหล่งนั้นเป็นค่าว่าง

\subsection{แบบจำลองทำนายผลการแข่งขัน}

การทำนายผลการแข่งขันฟุตบอลถูกกำหนดให้เป็นโจทย์ที่ให้ผลลัพธ์เป็นความน่าจะเป็นของ 3 กลุ่ม ได้แก่ ทีมเจ้าบ้านชนะ (H), เสมอ (D) และทีมเยือนชนะ (A) โครงงานนี้ใช้แบบจำลอง 2 แนวทางที่มีบทบาทต่างกัน ดังนี้

\paragraph{1) แบบจำลอง Double Poisson และการแก้ไขแบบ Dixon-Coles}
จำนวนประตูของทีมเจ้าบ้านและทีมเยือนถูกจำลองเป็นตัวแปรสุ่มแบบปัวซง (Poisson) สองตัว โดยให้ค่าลอการิทึมของอัตราการทำประตูเป็นฟังก์ชันเชิงเส้นของผลต่างคะแนน Elo ก่อนการแข่งขัน (หารด้วย 400) ซึ่งประมาณค่าด้วย Poisson Regression จากนั้นนำความน่าจะเป็นของสกอร์ทุกค่ามาสร้างตารางร่วม (Score Grid) แล้วรวมเป็นความน่าจะเป็นของ H, D และ A การแก้ไขแบบ Dixon-Coles \cite{dixon1997modelling} ปรับความน่าจะเป็นของสกอร์ต่ำ (0--0, 1--0, 0--1 และ 1--1) ด้วยพารามิเตอร์ $\rho$ เพื่อแก้ปัญหาที่การแจกแจงปัวซงอิสระประเมินความน่าจะเป็นของสกอร์เหล่านี้คลาดเคลื่อน โดยในโครงงานนี้เลือกค่า $\rho$ จากช่วงที่กำหนดด้วยค่าความควรจะเป็นสูงสุด การทำนายใช้วิธี Walk-forward คือทำนายแต่ละฤดูกาลด้วยแบบจำลองที่ฝึกจากฤดูกาลก่อนหน้าเท่านั้น

\paragraph{2) Gradient Boosting}
เป็นเทคนิค Ensemble Learning ที่สร้างต้นไม้ตัดสินใจขนาดเล็กหลายต้นต่อเนื่องกัน โดยแต่ละต้นเรียนรู้แก้ไขความคลาดเคลื่อนของต้นก่อนหน้า ในโครงงานนี้ใช้ \texttt{HistGradientBoostingClassifier} ของ Scikit-learn \cite{scikit-learn} เป็นแบบจำลองสำหรับวัดว่าตัวแปรกลุ่มใดให้สัญญาณต่อการทำนายผล โดยใช้วิธี Permutation Importance

\paragraph{3) Permutation Importance}
วัดความสำคัญของตัวแปรจากระดับที่ค่า Log Loss บนชุดทดสอบเพิ่มขึ้น เมื่อสลับค่าของตัวแปรนั้นแบบสุ่มโดยไม่เปลี่ยนค่าอื่น ตัวแปรที่เมื่อถูกสลับแล้วทำให้ Log Loss เพิ่มมากแสดงว่าให้ข้อมูลสำคัญต่อแบบจำลอง เนื่องจากตัวแปรผู้เล่นตัวจริง 22 ตำแหน่งมีความสัมพันธ์กันสูง จึงสลับค่าเป็นกลุ่มพร้อมกัน แทนการสลับทีละคอลัมน์

\paragraph{4) ตัวชี้วัดประสิทธิภาพ}
\textbf{Log Loss} วัดคุณภาพของความน่าจะเป็นที่ทำนาย (ยิ่งต่ำยิ่งดี) \textbf{Ranked Probability Score (RPS)} วัดความคลาดเคลื่อนของการแจกแจงสะสมของผลลัพธ์ที่เรียงลำดับ (ชนะ-เสมอ-แพ้) และ \textbf{Accuracy} วัดสัดส่วนที่ทำนายผลที่มีความน่าจะเป็นสูงสุดถูกต้อง โดยใช้ความน่าจะเป็นตามสัดส่วนผลการแข่งขันในอดีต (Class Prior) เป็นเกณฑ์เปรียบเทียบพื้นฐาน

\subsection{การทดสอบสมมติฐานทางสถิติ}

โครงงานนี้ใช้การทดสอบสมมติฐานเพื่อตรวจสอบข้อสังเกตเชิงปริมาณก่อนสร้างแบบจำลอง ได้แก่ การทดสอบ Paired t-test และ Wilcoxon Signed-rank Test (ทางเลือกที่ไม่ต้องสมมติว่าข้อมูลแจกแจงปกติ) เพื่อเปรียบเทียบจำนวนประตูของทีมเจ้าบ้านกับทีมเยือน และสัมประสิทธิ์สหสัมพันธ์ของ Pearson และ Spearman เพื่อวัดความสัมพันธ์ระหว่างผลต่างคะแนน Elo กับผลต่างประตู โดยกำหนดระดับนัยสำคัญที่ 0.05

ในส่วนนี้เป็นการทบทวนวรรณกรรมและงานวิจัยที่นำเทคนิควิทยาการข้อมูลและการเรียนรู้ของเครื่องมาใช้ในการทำนายผลกีฬา เพื่อหาแนวทางและช่องว่างในการพัฒนาโครงงาน

\subsection{การทำนายผลฟุตบอลด้วยแบบจำลองเชิงสถิติและอัตราต่อรอง}

งานวิจัยยุคแรกมักใช้สถิติการแข่งขันย้อนหลัง เช่น จำนวนประตูที่ทำได้ ฟอร์มเหย้า-เยือน ผ่านโมเดลเชิงสถิติตระกูล Poisson \cite{dixon1997modelling} หรือระบบจัดอันดับ Rating \cite{hvattum2010using, constantinou2013determining} ซึ่งจากการประเมินและทบทวนวรรณกรรมย้อนหลัง 40 ปีโดย Hubáček และคณะ \cite{hubacek2021forty} ที่ทดสอบกับชุดข้อมูลกว่า 2.1 แสนนัด พบว่าแบบจำลองที่ใช้เพียงผลสกอร์ย้อนหลังมีขีดจำกัดความแม่นยำอยู่เพียงร้อยละ 47.8--48.6 เท่านั้น ในขณะที่ราคาอัตราต่อรองจากตลาดเดิมพันกลับให้ความแม่นยำสูงกว่า (ประมาณร้อยละ 53--55) เนื่องจากสะท้อนข้อมูลเชิงลึกในตลาดได้อย่างรวดเร็ว อย่างไรก็ตาม การใช้เพียงอัตราต่อรองอย่างเดียวจะไม่สามารถอธิบายปัจจัยภายในหรือบริบทการเล่นของทีมได้ครบถ้วน

\subsection{การใช้ Machine Learning ร่วมกับตัวแปรสถิติเชิงลึกและข้อมูลบริบท}

งานวิจัยจำนวนมากใช้สถิติการครองบอล การยิงประตู และฟอร์มย้อนหลังเป็นตัวแปรสำหรับแบบจำลองการเรียนรู้ของเครื่อง อย่างไรก็ตาม งานวิจัยส่วนใหญ่มักมองข้ามข้อมูลระดับผู้เล่นและบริบทของตารางแข่งขัน เช่น ไลน์อัปตัวจริง ภาระการเล่นสะสมของนักเตะ และการแข่งขันรายการอื่นที่ทีมต้องลงเล่น ซึ่ง Berrar และคณะ \cite{berrar2019incorporating} ได้ชี้ให้เห็นว่าการดึงความรู้เฉพาะทางและบริบทแวดล้อม (Domain Knowledge) เช่น สถิติ xG และไลน์อัปตัวจริง เข้ามาประกอบ จะช่วยให้แบบจำลองทำนายผลได้แม่นยำยิ่งขึ้น

\subsection{ภาษา Python และไลบรารีสำหรับการประมวลผลข้อมูล}

ภาษา Python เป็นภาษาหลักที่ใช้ในการดำเนินโครงงาน เนื่องจากมีระบบนิเวศของไลบรารีที่สนับสนุนงานด้าน Data Science และ Data Engineering อย่างครบถ้วน ได้แก่

\begin{enumerate}[label=\arabic*)]
    \item \textbf{Polars, DuckDB และ PyArrow:} ใช้สำหรับการจัดการ ทำความสะอาด และประมวลผลตารางข้อมูลประสิทธิภาพสูง (High-performance DataFrames)
    \item \textbf{Pandera และ Pydantic:} ใช้สำหรับการตรวจสอบความถูกต้องของโครงสร้างข้อมูล (Data Schema Validation \& Data Contracts) และการตรวจสอบไฟล์ตั้งค่าของระบบ
    \item \textbf{Soccerdata:} ใช้ดึงข้อมูลจากแหล่งข้อมูลฟุตบอลสาธารณะ เช่น Understat
    \item \textbf{Scikit-learn และ SciPy:} ใช้พัฒนาแบบจำลอง (Poisson Regression, Gradient Boosting) การคำนวณตัวชี้วัด และการทดสอบสมมติฐานทางสถิติ \cite{scikit-learn}
    \item \textbf{Matplotlib:} ใช้ทำ Data Visualization เพื่อสำรวจข้อมูลและแสดงผลการวิเคราะห์
    \item \textbf{FastAPI และ Uvicorn:} ใช้พัฒนา API สำหรับเรียกดูตารางข้อมูลที่ผ่านการทำความสะอาดและผลการทำนายของแบบจำลอง
\end{enumerate}

\subsection{สภาพแวดล้อมและการประกันคุณภาพซอฟต์แวร์ (Development Environment \& Quality Control)}

\begin{enumerate}[label=\arabic*)]
    \item \textbf{ระบบบริหารจัดการสภาพแวดล้อมเสมือน (\texttt{uv}) และ Docker:} \texttt{uv} บริหารจัดการ Virtual Environment และไลบรารีความเร็วสูง พร้อมไฟล์ล็อกรุ่นของไลบรารี ส่วน Docker ช่วยให้รันท่อส่งข้อมูลและ API ได้ในสภาพแวดล้อมเดียวกัน
    \item \textbf{ระบบทดสอบซอฟต์แวร์และตรวจสอบโค้ดอัตโนมัติ:} ใช้ Pytest (พร้อมรายงานความครอบคลุมของการทดสอบ) และ Hypothesis สำหรับชุดทดสอบอัตโนมัติ ใช้ Ruff และ Pyright สำหรับตรวจรูปแบบและชนิดข้อมูลของโค้ด ใช้ pre-commit และ GitHub Actions ตรวจสอบก่อนบันทึกและทุกครั้งที่ส่งโค้ดขึ้นระบบ
    \item \textbf{เอกสารประกอบ:} ใช้ MkDocs จัดทำเอกสารอธิบายขั้นตอนของท่อส่งข้อมูล โครงสร้างตาราง (Schema) และคำสั่งที่ใช้งาน
    \item \textbf{แหล่งชุดข้อมูลสาธารณะ (Understat, Transfermarkt, Kaggle):} เป็นแหล่งข้อมูลผลการแข่งขัน ค่า xG สถิติรายบุคคลของผู้เล่น ปฏิทินการแข่งขันของสโมสร และผลการแข่งขันพรีเมียร์ลีกย้อนหลัง \cite{kaggle2024, transfermarkt2024, understat2024}
\end{enumerate}
