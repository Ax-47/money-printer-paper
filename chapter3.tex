ในการดำเนินโครงงาน "การวิเคราะห์และทำนายผลการแข่งขันฟุตบอลพรีเมียร์ลีกอังกฤษด้วยกระบวนการวิทยาการข้อมูล (English Premier League Match Analysis and Prediction Using Data Science Process)" ผู้จัดทำได้ออกแบบและพัฒนาท่อส่งข้อมูลเชิงโมดูลาร์ (Modular Data Pipeline) ตามกระบวนการวิทยาการข้อมูล เพื่อให้ระบบสามารถประมวลผลข้อมูลที่มีความซับซ้อน ป้องกันปัญหาข้อมูลอนาคตรั่วไหล (Data Leakage) และรองรับการทดสอบคุณภาพระบบอย่างเป็นระบบ โดยแบ่งขั้นตอนการดำเนินงานออกเป็น 5 ส่วนหลัก ดังนี้

\begin{enumerate}[label=\arabic*)]
    \item การวิเคราะห์และกำหนดแนวทางการพัฒนาโครงงาน
    \item การเก็บรวบรวมข้อมูลและการประมวลผลเบื้องต้น (Data Collection \& Ingestion)
    \item การตรวจสอบความถูกต้องและการเตรียมข้อมูล (Data Schema Validation \& Entity Resolution)
    \item การวิศวกรรมฟีเจอร์และการออกแบบสถาปัตยกรรมระบบ (Feature Engineering \& System Architecture)
    \item การพัฒนาแบบจำลอง การแบ่งชุดข้อมูล และกรอบการประเมินผล (Model Development \& Evaluation Framework)
\end{enumerate}

% -----------------------------------------------------------
\section{การวิเคราะห์และกำหนดแนวทางการพัฒนาโครงงาน}
% -----------------------------------------------------------

การทำนายผลการแข่งขันฟุตบอลมีความซับซ้อนสูงเนื่องจากปัจจัยรอบด้านที่ส่งผลต่อผลการแข่งขัน โครงงานนี้จึงมุ่งเน้นการใช้ประโยชน์จากข้อมูลสถิติล่วงหน้า ข้อมูลคุณลักษณะเชิงลึก และประวัติการแข่งขันย้อนหลัง โดยมีแนวทางการดำเนินงานดังนี้

\begin{enumerate}[label=\arabic*)]
    \item \textbf{ศึกษาทฤษฎีและงานวิจัยที่เกี่ยวข้อง:} ศึกษาหลักการคำนวณระบบประเมินศักยภาพเชิงสัมพัทธ์ (Elo Rating System) \cite{hvattum2010using}, ทฤษฎีค่าความน่าจะเป็นของประตูที่คาดว่าจะเกิดขึ้น (Expected Goals: xG) \cite{understat2024}, การคำนวณดัชนีความเหนื่อยล้าสะสม (Fatigue Index) และการทำวิศวกรรมฟีเจอร์แบบอนุกรมเวลา (Time-Series Feature Engineering)
    \item \textbf{กำหนดขอบเขตและเป้าหมายการทำนาย:} กำหนดเป้าหมายการทำนายผลการแข่งขันออกเป็น 3 รูปแบบ (Multi-class Classification) ได้แก่ เจ้าบ้านชนะ (Home Win: H), เสมอ (Draw: D), และ ทีมเยือนชนะ (Away Win: A) สำหรับแมตช์การแข่งขันฟุตบอลพรีเมียร์ลีกอังกฤษ
    \item \textbf{กำหนดเครื่องมือและสภาพแวดล้อมการพัฒนา:} พัฒนาระบบด้วยภาษา Python 3.10+ ร่วมกับเครื่องมือบริหารจัดการสภาพแวดล้อมเสมือนและการจัดสรรไลบรารีประสิทธิภาพสูง (\texttt{uv}) ควบคู่กับไลบรารีวิเคราะห์ข้อมูลตารางขนาดใหญ่ (Polars), เครื่องมือตรวจสอบสัญญาข้อมูล (Pandera และ Pydantic), ไลบรารีเรียนรู้ของเครื่อง (Scikit-learn), ระบบทดสอบซอฟต์แวร์อัตโนมัติ (Pytest) และระบบตรวจทานคุณภาพโค้ด (Ruff)
\end{enumerate}

\section{การเก็บรวบรวมข้อมูลและการประมวลผลเบื้องต้น (Data Collection \& Ingestion)}
% -----------------------------------------------------------

\subsection{การเก็บรวบรวมข้อมูลดิบแบบหลายแหล่ง (Multi-Source Data Scraping)}

ผู้จัดทำได้พัฒนาระบบดึงข้อมูลอัตโนมัติ (Automated Data Collection Pipeline) เพื่อรวบรวมข้อมูลจาก 4 แหล่งข้อมูลหลักภายนอกที่มีโครงสร้างหลากหลาย ดังนี้

\begin{enumerate}[label=\arabic*)]
    \item \textbf{ฐานข้อมูลสถิติการแข่งขันและผู้เล่น (FBref):} ดึงข้อมูลตารางการแข่งขัน ผลการแข่งขันจริง สถิติลายบุคคลของนักเตะในแต่ละนัด และสถิติเชิงลึกหลังจบเกม \cite{fbref2024}
    \item \textbf{ฐานข้อมูลวิเคราะห์โอกาสทำประตู (Understat):} ดึงข้อมูลสถิติค่าความคาดหวังในการทำประตู (xG) สถิติกราฟการยิงประตูรายนัด และรายชื่อผู้เล่น 11 ตัวจริง (Lineups) \cite{understat2024}
    \item \textbf{ฐานข้อมูลประเมินมูลค่าสโมสร (Transfermarkt):} ดึงข้อมูลมูลค่าการตลาดรวมของสโมสร (Team Market Value) เพื่อใช้เป็นตัวแทนสะท้อนขนาดและศักยภาพขุมกำลังนักเตะ \cite{transfermarkt2024}
    \item \textbf{ฐานข้อมูลอัตราต่อรองประวัติศาสตร์ (Kaggle / Historical Odds):} รวบรวมสถิติราคาต่อรองการเดิมพันย้อนหลัง (Bookmaker Betting Odds) เพื่อนำมาคำนวณหาความน่าจะเป็นประเมินโดยตลาด (Implied Probabilities) \cite{kaggle2024}
\end{enumerate}

\subsection{การตรวจสอบความถูกต้องของข้อตกลงข้อมูล (Data Schema Validation)}

เพื่อป้องกันข้อผิดพลาดจากโครงสร้างข้อมูลดิบที่ไม่สอดคล้องกัน ระบบได้ประยุกต์ใช้แนวคิดสัญญาข้อมูล (Data Contracts) ผ่านการตรวจสอบความถูกต้องแบบอัตโนมัติ โดยแบ่งการตรวจออกเป็น 3 ระดับ ดังนี้

\begin{itemize}
    \item \textbf{โครงสร้างข้อมูลดิบ (Raw Data Schema):} ตรวจสอบไฟล์ข้อมูลดิบหลังสแครปว่ามีคอลัมน์จำเป็นและชนิดข้อมูลพื้นฐานถูกต้องหรือไม่
    \item \textbf{โครงสร้างข้อมูลสะอาด (Clean Data Schema):} ตรวจสอบประเภทข้อมูล ขอบเขตตัวเลขที่เป็นไปได้ และขจัดค่าว่าง (Null Values) หลังผ่านกระบวนการทำความสะอาด
    \item \textbf{โครงสร้างข้อมูลรวม (Joined Data Schema):} ตรวจสอบความสมบูรณ์และความสัมพันธ์ของตารางข้อมูลรวมก่อนส่งต่อไปยังกระบวนการสร้างตัวแปรทำนาย
\end{itemize}

\subsection{การทำความสะอาดและจับคู่ข้อมูล (Entity Resolution)}

เนื่องจากชื่อสโมสรฟุตบอลในแต่ละแหล่งข้อมูลมีการบันทึกที่ไม่ตรงกัน เช่น \texttt{"Man Utd"}, \texttt{"Manchester Utd"} และ \texttt{"Manchester United"} ระบบจึงได้นำกระบวนการแปลงเอนทิตีให้เป็นมาตรฐาน (Entity Resolution) มาใช้ผ่านพจนานุกรมเทียบเคียงชื่อสโมสร (Name Mapping Dictionary) โดยกำหนดรหัสสโมสรมาตรฐาน (Canonical Team Code) เพื่อเชื่อมโยงตารางข้อมูล (Data Joining) จากทุกแหล่งเข้าด้วยกันอย่างถูกต้อง 100\%

\subsection{การคำนวณคะแนนความแข็งแกร่งเชิงสัมพัทธ์ (Elo Rating Calculation)}
ระบบทำการคำนวณคะแนนความแข็งแกร่งของสโมสรย้อนหลังตามลำดับเวลา โดยปรับปรุงค่า Elo หลังจบทุกแมตช์การแข่งขันตามผลการแข่งขันจริงและผลต่างประตู ซึ่งค่าความน่าจะเป็นคาดหวัง ($E_A$) และการปรับปรุงคะแนน Elo ใหม่ ($R'_A$) คำนวณได้จากสมการที่ (\ref{eq:elo_expected}) และ (\ref{eq:elo_update})

\begin{equation}
    E_A = \frac{1}{1 + 10^{(R_B - R_A)/400}}
    \label{eq:elo_expected}
\end{equation}

\begin{equation}
    R'_A = R_A + K \cdot (S_A - E_A)
    \label{eq:elo_update}
\end{equation}

โดยที่ $R_A, R_B$ คือคะแนน Elo ของทีมเจ้าบ้านและทีมเยือนก่อนแข่ง, $S_A$ คือผลการแข่งขันจริง ($1$ เมื่อชนะ, $0.5$ เมื่อเสมอ, $0$ เมื่อแพ้) และ $K$ คือค่าพารามิเตอร์การปรับน้ำหนัก ($K=20$) ตัวอย่างขั้นตอนการคำนวณและอัปเดตคะแนนแสดงดังรายการที่ \ref{lst:elo_code}

\noindent
\begin{minipage}{\textwidth}
\begin{lstlisting}[language=Python, caption={ฟังก์ชันการคำนวณและปรับปรุงคะแนน Elo Rating}, label={lst:elo_code}]
def update_elo(home_elo: float, away_elo: float, home_score: int, away_score: int, k: float = 20.0):
    # คำนวณความน่าจะเป็นคาดหวัง (Expected Outcome)
    e_home = 1.0 / (1.0 + 10.0 ** ((away_elo - home_elo) / 400.0))
    e_away = 1.0 - e_home
    
    # กำหนดผลลัพธ์จริง (Actual Outcome)
    if home_score > away_score:
        s_home, s_away = 1.0, 0.0
    elif home_score == away_score:
        s_home, s_away = 0.5, 0.5
    else:
        s_home, s_away = 0.0, 1.0
        
    # ปรับปรุงคะแนน Elo ใหม่
    new_home_elo = home_elo + k * (s_home - e_home)
    new_away_elo = away_elo + k * (s_away - e_away)
    return new_home_elo, new_away_elo
\end{lstlisting}
\end{minipage}
\subsection{การคำนวณดัชนีความเหนื่อยล้าสะสม (Fatigue Index Calculation)}
ระบบคำนวณตัวแปรความเหนื่อยล้าของสโมสรโดยพิจารณาจากจำนวนวันพักผ่อน (Days Rest) ระหว่างการแข่งขันนัดปัจจุบันกับนัดก่อนหน้า ควบคู่กับความหนาแน่นของโปรแกรมการแข่งขันย้อนหลังในช่วงเวลา 14 ถึง 30 วัน เพื่อให้แบบจำลองสามารถประเมินสภาวะความอ่อนล้าของนักเตะในทีมได้

\subsection{การคำนวณค่าเฉลี่ยเคลื่อนที่และการป้องกันข้อมูลรั่วไหล (Rolling Average Statistics)}
ระบบทำการสร้างฟีเจอร์ฟอร์มการเล่นย้อนหลัง $N$ นัด (Rolling Windows $N=3, 5, 10$) สำหรับตัวแปรสำคัญ ได้แก่ ประตูที่ยิงได้ ประตูที่เสีย ค่า xG และ xGA โดยการคำนวณจะกำหนดให้ใช้เฉพาะข้อมูลการแข่งก่อนวันแข่งขันจริง ($T-1, T-2, \dots, T-N$) เพื่อป้องกันปัญหาข้อมูลอนาคตรั่วไหลเข้าสู่แบบจำลอง (Data Leakage)

\subsection{การแปลงราคาต่อรองเป็นค่าความน่าจะเป็น (Implied Probabilities Conversion)}
แปลงราคาต่อรองจากเจ้ามือรับพนัน (Bookmaker Odds) ให้เป็นค่าความน่าจะเป็นประเมินโดยตลาด (Implied Probabilities) พร้อมขจัดค่าส่วนต่างกำไรของตลาด (Margin Overround) เพื่อนำมาใช้เป็นตัวแปรทำนายและใช้เป็นเกณฑ์อ้างอิงมาตรฐาน (Benchmark) ในการวัดประสิทธิภาพโมเดล

\subsection{การแบ่งชุดข้อมูลตามลำดับเวลา (Temporal Train-Test Split)}
เนื่องจากข้อมูลการแข่งขันฟุตบอลเป็นข้อมูลอนุกรมเวลา (Time-Series Data) การประเมินผลจึงต้องแบ่งชุดข้อมูลตามลำดับเวลาจริง (Temporal Split) โดยกำหนดให้ชุดข้อมูลการแข่งขันในอดีต (เช่น ฤดูกาล 2018/19--2022/23) เป็นชุดข้อมูลฝึกสอน (Training Set) และใช้นัดการแข่งขันในฤดูกาลล่าสุด (เช่น ฤดูกาล 2023/24) เป็นชุดข้อมูลทดสอบ (Test Set) เพื่อจำลองสถานการณ์ทำนายอนาคตในโลกจริงและป้องกันการนำข้อมูลอนาคตมาฝึกสอนโมเดล

\subsection{การเลือกและการฝึกสอนแบบจำลอง (Model Training \& Tuning)}
ผู้จัดทำได้เลือกใช้แบบจำลองการเรียนรู้ของเครื่องประเภทจำแนกหลายกลุ่ม (Multi-class Classification) ได้แก่ Logistic Regression, Decision Tree และ Random Forest โดยทำการค้นหาพารามิเตอร์ที่เหมาะสมที่สุด (Hyperparameter Tuning) และคำนวณระดับความสำคัญของตัวแปรทำนาย (Feature Importance) เพื่อประเมินปัจจัยที่มีผลต่อการทำนาย

\section{การทดสอบและการประกันคุณภาพระบบ (Testing \& Quality Assurance Framework)}
% -----------------------------------------------------------

\subsection{การทดสอบซอฟต์แวร์อัตโนมัติ (Automated Unit Testing)}
โครงงานนี้ให้ความสำคัญกับความถูกต้องและน่าเชื่อถือของระบบประมวลผลข้อมูล โดยได้จัดทำชุดทดสอบอัตโนมัติ (Unit Tests) เพื่อตรวจสอบความถูกต้องของฟังก์ชันคำนวณสถิติและการแปลงข้อมูลในระบบก่อนนำไปใช้งานจริง

\subsection{ดัชนีการประเมินประสิทธิภาพแบบจำลอง (Evaluation Metrics)}
การประเมินประสิทธิภาพของแบบจำลองบนชุดข้อมูลทดสอบวัดผลผ่านตัวชี้วัดทางสถิติที่ครอบคลุม ดังนี้

\begin{enumerate}[label=\arabic*)]
    \item \textbf{Classification Metrics:} คำนวณค่า Accuracy, Precision, Recall และ F1-Score สำหรับผลการแข่งขันทั้ง 3 คลาส ($H, D, A$)
    \item \textbf{Multi-Class Log Loss:} วัดความแม่นยำของการประมาณค่าความน่าจะเป็น คำนวณได้จากสมการที่ (\ref{eq:logloss})
    \begin{equation}
        \text{Log Loss} = -\frac{1}{N} \sum_{i=1}^{N} \sum_{j=1}^{M} y_{ij} \log(p_{ij})
        \label{eq:logloss}
    \end{equation}
    โดยที่ $N$ คือจำนวนแมตช์ทั้งหมด, $M$ คือจำนวนคลาส ($M=3$), $y_{ij}$ คือค่าจริง (1 หรือ 0) และ $p_{ij}$ คือค่าความน่าจะเป็นที่แบบจำลองทำนาย
\end{enumerate}
